为什么我们仍然需要学习编程

在去年的时候有一个视频，论证当下AI对我们程序员的影响，台下有一位观众提出质疑：可能今后AI发展会让一个程序员不需要有编写代码的能力，但是当下是不可行的，台上的人发表了一个逆天的言论：你凭什么剥夺一个不会写代码的人写代码的权利（大致就这意思）

通过上述的一个例子，已经把我们当下的情况全部给罗列出来，今年AI的发展相比去年已经是一个质的飞跃，不少人提出了一个问题，“自然语言编程”能不能像高级语言替代汇编语言一样，最后我们All in AI

这句话在当下一定是不对的，如果你的代码能力不够，你其实连让AI生成什么的能力也没有，说白了你连当驾驶员都不会；那么紧接着你的阅读源码的能力也没有，所有的东西最后都需要AI的帮助，效率下降，AI时代你更应该有读代码的能力；同时你也没有修改AI的能力，很多时候AI说的确实没有错，但是对于你来说不适用；同时你是嵌入式方向，从理论到实践，从仿真到实机的gap比你想的多。总而言之，你需要学代码

面向对象编程

封装：将数据和操作数据的函数放在同一个类中，并通过 private/public 控制外部访问

继承：子类继承父类的成员和接口，用于表示 is-a 关系。

多态：父类定义统一接口，不同子类实现不同功能，通常通过 virtual 实现

构造函数对象创建时自动调用，用于初始化成员变量和建立对象状态Robot(double position) : position_(position){}更推荐初始化列表

析构函数对象生命周期结束时自动调用，主要用于释放资源~Robot();更推荐智能指针

智能指针

unique_ptr独占所有权，一个对象只能有一个 unique_ptr 管理，无法复制但是可以移动所有权

shared_ptr共享所有权，多个 shared_ptr 可以共同管理一个对象，与unique_ptr相对

STL

std::vector<int> v{1, 2, 3, 4, 5};，将多个数字放在一个容器中，底层是一段连续内存，通过迭代器访问数据，内部封装了多个成员函数可以直接调用，常见也常用的容器就是vector，array

reserve只预留容量（capacity）、不改size，用来避免多次扩容时反复搬移元素

push_back直接将元素追加到末尾，重新分配内存会导致原来的迭代器失效

提问：为什么 vector 的迭代器支持 it + n，而 list 的迭代器不支持？

Lambda

匿名函数对象：编译器会为它生成一个闭包类（可以理解成内部定义了一个重载了 operator() 的结构体），捕获的变量就是该类的成员

const

定义一个变量，但是不可以直接修改，最常用的是void fun(const std::vector<double>& v)

对于外部传进来的变量只读，不进行修改，保证外部的变量不会因为这个函数改变

提问：如果不加const而直接加&是什么意思？

static

static int count = 0;静态变量，直到程序结束一直存在

作为类中的变量，在实例化的时候，所有的实例化成员都指向的是一个static变量

static int global_value;这个变量只有在当前的cpp文件中可见，对其他的文件不可见

提问：static在函数中，全局/文件作用域的变量或函数，和在类中调用分别有什么不同

auto

auto 用于让编译器根据初始化表达式自动推导变量类型，属于编译期类型推导，不是动态类型

提问：为啥有的时候不推荐用auto

内联函数

使用的是inline， 仅仅是作为建议，将原本的函数调用（压栈、跳转、返回）替换成直接展开的函数体计算

动态和静态

先说java，因为这个考试会考：static方法里没有this，只能访问静态成员；要调用非静态成员，必须先把对象实例化出来，再用这个对象（或指向它的引用）去调用。static方法属于类、不依赖对象，可以直接用类名调用

再说回c++，虚函数就是可以支持多态的函数，如果是普通的函数，那他就不支持多态，是静态绑定

类的static数据成员要在类外定义（C++17起可以用inline在类内定义），可以直接通过类名访问，生命周期贯穿整个程序

析构函数负责清理对象持有的资源，对象本身的内存由delete回收（栈对象由栈帧回收）

虚函数

当进行Animal* p = &dog;的时候，p->speak();仍然是指向的是父类的函数，这时候如果将父类的成员函数变成virtual，这样最后调用的还是dog中已经override的成员函数

编写方法提倡使用class Dog : public Animal{ public: void speak() override; };

编译器可以检查是否真的覆写了该成员函数，原因是函数签名有一点不一样就不算override,比如const,函数名打错了等等

虚函数最终的常见使用还是提供接口，工厂模式等，甚至还有多态运算符和虚析构函数，这里不做过多说明

纯虚函数：子类要实现（能被实例化）就必须override,语法就是在虚函数后面等于0，同时这意味着无法实例化

注意当虚函数被重写的时候，属于动态

提问：你是否自己能写出一个使用虚函数提供接口的父类，然后再子类中重新override它？什么是动态和静态？

throw栈展开

C++ 的异常不是 return 码，而是一个 运行时控制流跳转机制，这个过程叫做栈展开，遇到throw的时候，会对已构造的局部对象依次调用析构函数退栈，相比较传统的暴力退出，其无需挨个嵌套return,同时资源管理更完善

static_cast(expr) 是静态类型转换运算符，不是模板

assert(cond) 在条件为假时触发断言失败并终止程序，条件成立时什么都不做
