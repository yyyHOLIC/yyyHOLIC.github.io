前言

不要跟风去使用linux作为日常生产力，这其实是很费力不讨好的事情，甚至在机器人领域，很多linux的配置操作要比windows还要费劲，至于mac，由于用户的群体多，甚至比linux的软件适配要好

什么是linux

就是一个开源的内核，初学者会把内核还有发行版连在一起，但是Linux不等于Ubuntu，内核负责是硬件和软件之间的调度，首先是自带的驱动程序，负责与底层的硬件连接，其次是相关的shell(终端命令)还有或者GUI(图形化界面，会与之同时出现的是(QT和Electron)负责应用程序

与windows的区别

1.高度的可定制化，相比win更加的自由，你可以通过配置文件更改任何你想更改的东西，这同时也会增加风险，你的windows直接就有可视化的桌面，但是linux本身并不包含，GNU(常见工具包，包含gcc,make等)工具，系统服务同理

2.更适合程序员和服务器的OS(操作系统)，主要得益于其文件管理，分为根目录(全局环境)和家目录(用户环境)，使其环境配置更加舒适，但是不推荐linux作为日常生产力工具

3.无病毒，得益于开源

4.其文件架构使包管理器(apt,yay,pacman等)非常好用，进一步使其环境稳定可控

不同发行版的区别

刚才说明了windows的区别，这个时候你会发现windows已经全部打包好了，但是linux只是一个内核，他需要其他的工具才能和windows一样，这就是发行版该干的事

1.桌面环境不同(gnome,KDE)，顺带说一下x11还有wayland，gnome在去年抛弃了x11全面转为wayland，ubutnu使用的默认桌面就是gnome,所以最新的软件应该是支持wayland,有些软件不支持可以使用xwayland作为兼容，但是这不是万能的

Linux开机都发生了些什么(方便大家理解Linux内核和硬件的联动)

1.BIOS/UEFI负责硬件的初始化，包括cpu,内存，为什么在这里提到他呢，最重要的是在嵌入式领域中，你更多的会听到设备树的概念，其目标和BIOS差不多，查找硬件的地址，让计算机知道有哪些设备，复杂的不在这里展开

2.bootloader(就是grub，rEFland)，负责寻找内核，将内核放在内存中，加载设备树等

3.加载linux kernel 内核还可以一直更新，甚至可以重新编译内核

4.initramfs临时根目录

5.启动各种系统服务，可自定义，配置需要开机自启的软件的脚本等

Linux深入学习

说是深入学习，但是也给大家只列出最重要部分，有一说一现在agent的存在也不需要知道那么多

1.重要思想，linux的一切以文件为主，将硬件抽象成文档的形式，最直观的例子就是使用usb，会在/dev/ttyUSB*显示，还有/proc会有内核信息，/sys就是系统信息，所以了解根目录下的每个文件作用是很重要的

2.linux权限，这个也不多说了，平时常见的就是以sudo身份运行，还有自己创建脚本的时候，需要chomd +x来给予脚本运行的权利，具体的自己去了解

3.进程和线程，这个在windows下大家也了解过，主要有PID,父进程，子进程，僵尸进程等，还有使用ps管理进程等，方便管理线程的工具是htop，top

4.Shell，在终端下，最常见的配置环境就是使用export，在终端内作为临时的环境变量，如果想要自动调用相关的环境而不是每次需要export的话，可以配置./bashrc文件，或编写launch，sh等

5.网络相关配置，必须学会使用ssh，这个是嵌入式开发很重要的远程开发工具，原理就是在同一局域网下得知对方的ip地址，通过22号端口进行通信，网络常见命令有curl，ping等

6.存储和硬盘，硬盘是挂载在系统上的，通过lsblk得知自己的硬盘和分区，linux常见硬盘格式ext4，不过其实已经被淘汰了，不如btrfs。windows常见的硬盘格式是ntfs。还要知道mount挂载命令，知道格式化是什么意思，UUID是设备号，通过唯一得知的UUID方便挂载，可以直接读取ntfs文件格式的硬盘，但是windows不可直接读取ext4

7.容器，为什么需要容器，就是为了做环境隔离，更好的配置软件软件，如果你学过python那么一定了解虚拟环境，开一个新项目就使用pyenv或者conda创建一个虚拟环境是一个好的习惯，容器的道理也差不多，常见的容器就是Docker还有Podman，如果想使用不同的发行版使用distrobox

一、什么是 Linux

严格来说，Linux 是一个开源的操作系统内核，不是完整的桌面操作系统。内核主要负责：

  • 管理 CPU、内存、磁盘和网络设备；
  • 调度进程和线程；
  • 提供文件系统、网络协议栈等基础能力；
  • 通过驱动程序与硬件通信；
  • 向用户空间程序提供系统调用接口

我们平时安装的 Ubuntu、Debian、Fedora 和 Arch Linux 是 Linux 发行版。一个发行版通常包含：

  • Linux 内核；
  • GNU 等项目提供的用户空间工具
  • Shell，例如 Bash 或 Zsh
  • 初始化和服务管理系统，例如 systemd
  • 包管理器和软件仓库
  • 可选的图形界面、桌面环境和常用软件

因此，Linux 不等于 Ubuntu，Ubuntu 只是众多 Linux 发行版中的一种

还要区分几个容易混淆的概念：

  • 终端模拟器：显示和输入文本的窗口，例如 GNOME Terminal、kitty
  • Shell：解释命令的程序，例如 Bash、Zsh
  • 桌面环境：一整套图形桌面，例如 GNOME、KDE Plasma，还有一个很好看的，但是不好用
  • GUI 工具包：开发图形应用的组件，例如 GTK、Qt
  • 应用框架：Electron 可用于开发跨平台桌面应用

二、Linux 与 Windows 的主要区别

1. 系统组件更加模块化

Windows 通常以完整产品的形式提供桌面、系统工具和服务。Linux 发行版则可以组合不同的内核版本、桌面环境、Shell、包管理器和服务。模块化带来了自由，也意味着用户需要理解更多组件之间的关系。

2. 配置和自动化更偏向文本

Linux 中许多设置保存在文本配置文件里，常用命令也容易写入脚本。这非常适合批量部署、版本管理和远程维护，但错误的配置同样可能让服务或桌面无法启动。修改关键配置前，应先备份并确认恢复方法。

3. 文件系统只有一棵目录树

Windows 常用 C:、D: 区分不同卷。Linux 从根目录 / 开始组织所有文件，其他磁盘、分区和网络存储需要挂载到这棵目录树中的某个目录。

用户自己的文件通常位于 /home/用户名，管理员 root 的家目录则是 /root。这里的“根目录 /”与“root 用户”不是同一个概念。

4. 权限模型贯穿整个系统

文件和进程都有所有者及权限。普通用户默认不能修改系统关键文件，需要时再通过 sudo 临时执行管理操作。这能减少误操作的影响，但不能代替备份和安全配置。

5. Linux 并非没有病毒

Linux 同样存在恶意软件、供应链攻击、弱口令入侵和配置漏洞。开源有利于审计和修复，但不等于天然安全。及时更新、最小权限、可靠的软件源、SSH 密钥和防火墙仍然很重要。

三、发行版应该怎样选择

发行版之间最重要的差别是更新策略、软件仓库、默认配置和支持周期，而不只是桌面外观。

Ubuntu / Debian （现在只推荐用这个，其他只做了解）

  • Ubuntu LTS 重视长期稳定和兼容性，建议还是使用22.04
  • ROS 官方通常优先支持特定版本的 Ubuntu,不同的发行版之间只要没有使用特定的接口API，ROS的源码可以互通
  • 软件版本可能不新，但安全和关键错误修复会以补丁形式提供

Fedora（没用过，让AI告诉你们）

  • 软件较新，同时保留相对规范的发布周期
  • 适合开发和学习较新的 Linux 技术
  • 默认使用 SELinux，安全机制更严格

Arch Linux（我在使用的系统）

  • 滚动更新，软件版本新，可定制程度高，导致软件更新快，bug能及时修，所以可以日常使用
  • Arch Wiki 这个社区很牛逼，但是现在有ai了，不太用得上了
  • 某些只对特定 Ubuntu 版本提供支持的软件，在 Arch 上可能需要自行适配，但是不是所有都能适配好，比如ROS

包管理器不同

  • Debian / Ubuntu：apt，底层包格式通常是 .deb
  • Fedora：dnf，底层包格式通常是 .rpm
  • Arch Linux：pacman
  • yay 是常见的 Arch User Repository 辅助工具，不是 Arch 官方包管理器本身

桌面显示系统

Linux 桌面常见两套显示协议：X11 和 Wayland。Wayland 正逐渐成为主流桌面的默认选择，XWayland 可以让许多旧的 X11 应用在 Wayland 会话中运行，但某些远程控制、录屏、输入法或专业软件仍可能存在兼容问题，大部分GUI都没有办法解决，现在最新的ubuntu开始像Wayland转变，gnome在去年就不支持x11了，目前有好转，比如飞书的共享屏幕无bug，但是腾讯会议有

四、先学会这些基本操作

以下示例默认使用 Bash，路径和文件名区分大小写

1. 确认自己在哪里

pwd                    # 显示当前目录
ls                     # 列出当前目录内容
ls -lah                # 显示隐藏文件、权限和易读的文件大小
cd /path/to/directory  # 进入指定目录
cd ..                  # 返回上一级目录
cd ~                   # 回到当前用户的家目录
cd -                   # 回到上一次所在目录

. 表示当前目录，.. 表示上一级目录，~ 表示当前用户的家目录。以 / 开头的是绝对路径，否则通常是相对路径

2. 创建、复制、移动和删除

mkdir project                 # 创建目录
mkdir -p work/demo/src        # 连同缺失的父目录一起创建
touch notes.txt               # 创建空文件或更新时间戳
cp source.txt backup.txt      # 复制文件
cp -r source_dir backup_dir   # 递归复制目录
mv old.txt new.txt            # 重命名文件
mv file.txt target_dir/       # 移动文件
rm file.txt                   # 删除文件
rm -r old_dir                 # 递归删除目录

rm 默认不会进入回收站。不要把 rm -rf 当作普通删除命令，更不要在没有理解路径和变量值时配合 sudo 使用。删除前可以先用 ls 检查目标，重要数据应有备份

3. 查看和搜索内容

cat file.txt                   # 输出较短文件
less long.log                  # 分页查看长文件，按 q 退出
head -n 20 file.txt            # 查看前 20 行
tail -n 50 app.log             # 查看最后 50 行
tail -f app.log                # 持续查看新增日志
find . -name '*.yaml'          # 按文件名查找
grep -Rni 'error' ./logs       # 在目录中递归搜索文本

向搜索引擎或 AI 提问时，至少提供发行版及版本、完整命令、完整报错、预期行为和已经尝试过的方法。不要只提供一句“运行不了”。也不要在没看懂的情况下执行来源不明的命令，尤其是带有 sudo、curl ... | sh、磁盘设备路径或递归删除的命令

5. 安装和更新软件

Ubuntu / Debian：

sudo apt update
sudo apt install <package>
sudo apt remove <package>
apt search <keyword>

Arch Linux：

sudo pacman -Syu
sudo pacman -S <package>
sudo pacman -Rns <package>
pacman -Ss <keyword>

五、理解 Linux 的目录

Linux 常被概括为“一切皆文件”。更准确地说，Linux 尽量通过统一的文件描述符和文件式接口访问普通文件、设备、管道及部分内核信息，但并不是所有对象都是普通磁盘文件

目录 作用
/ 整棵目录树的起点
/home 普通用户的家目录
/root root 用户的家目录
/etc 系统级配置文件
/var 日志、缓存、数据库等经常变化的数据
/usr 大部分用户空间程序、库和共享资源
/bin、/sbin 基础命令；现代发行版中常链接到 /usr 下的目录
/tmp 临时文件，可能在重启后被清理
/dev 设备节点，例如磁盘和串口
/proc 进程和内核状态的虚拟文件系统
/sys 设备、驱动和内核对象的虚拟文件系统
/run 本次启动期间的运行时状态
/mnt、/media 手动或自动挂载存储设备的位置
/opt 可选的第三方软件

USB 转串口设备可能显示为 /dev/ttyUSB0 或 /dev/ttyACM0，具体名称取决于驱动和设备类型。不要依赖编号永远不变；长期使用时可以考虑 /dev/serial/by-id/ 中的稳定链接或编写 udev 规则，当然还有by-path，就是固定的usb物理接口

七、Shell、环境变量和脚本

环境变量是进程运行环境中的键值数据。Shell 启动的子进程会继承已导出的环境变量：

export MY_PROJECT="$HOME/work/demo"
echo "$MY_PROJECT"
env | grep MY_PROJECT
unset MY_PROJECT

这类设置只在当前 Shell 及其子进程中有效。需要长期生效时，先确认当前 Shell：

echo "$SHELL"

Bash 交互配置通常写在 ~/.bashrc，Zsh 通常写在 ~/.zshrc。修改后可重新打开终端，或在确认配置无误后执行：

source ~/.bashrc

不要反复把同一行追加到配置文件。环境配置出错时，可以执行 bash --noprofile --norc 启动一个不加载用户配置的 Bash 来排查

一个最小 Shell 脚本如下：

#!/usr/bin/env bash
set -euo pipefail

project_dir="${1:-$HOME/work/demo}"
printf 'Project: %s\n' "$project_dir"

将其保存为 show-project.sh 后执行，脚本大部分都会出现权限问题导致的bug

chmod +x show-project.sh
./show-project.sh

Shell 脚本适合编排命令和自动化系统任务；复杂的数据处理或大型程序更适合 Python、Go 等语言。ROS 的 launch 文件用于描述节点启动关系，不等同于普通 Shell 配置脚本。

八、进程、服务和日志

1. 进程

进程是正在运行的程序实例，每个进程有 PID，并可能有父进程和子进程。线程是进程内部的执行单元。

ps aux                         # 查看进程快照
ps -ef --forest                # 按父子关系显示进程
top                            # 动态查看资源占用
htop                           # 更友好的交互界面，需要单独安装
pgrep -af <keyword>            # 按名称查找进程
kill <PID>                     # 默认发送 SIGTERM，请求正常退出
kill -9 <PID>                  # 发送 SIGKILL，只应作为最后手段

僵尸进程已经结束，但父进程尚未回收它的退出状态。僵尸进程本身不再运行，也不能靠 kill -9 清除，应该检查其父进程为什么没有正确回收子进程。

2. systemd 服务

许多主流发行版使用 systemd 管理系统服务：

systemctl status ssh           # 查看服务状态
sudo systemctl start ssh       # 本次启动服务
sudo systemctl stop ssh        # 停止服务
sudo systemctl restart ssh     # 重启服务
sudo systemctl enable ssh      # 设置开机启动
sudo systemctl enable --now ssh # 立即启动并设置开机启动

服务失败时，先看状态和日志，而不是连续重装：

systemctl status <service> --no-pager
journalctl -u <service> -b
journalctl -u <service> -f
journalctl -p warning..alert -b

九、网络与 SSH

SSH 是远程登录、传输文件和远程开发的基础工具。SSH 不要求设备处于同一局域网，只要网络路由、防火墙和访问控制允许即可。服务端默认监听 TCP 22 端口，但管理员可以修改

常用网络检查命令：

ip addr                         # 查看网络接口和地址
ip route                        # 查看路由表
ping -c 4 192.168.1.10          # 测试 ICMP 连通性
ss -lntup                       # 查看正在监听的端口
curl -I https://example.com     # 请求 HTTP 响应头
getent hosts example.com        # 通过系统配置解析域名

连接远程主机：

ssh user@192.168.1.10
ssh -p 2222 user@example.com
scp file.txt user@host:/tmp/
rsync -av --progress project/ user@host:/srv/project/

推荐使用密钥认证：

ssh-keygen -t ed25519
ssh-copy-id user@host

十、磁盘、文件系统和挂载

物理磁盘通常先划分分区，再在分区上创建文件系统，最后挂载到某个目录后使用。

lsblk -f                        # 查看块设备、文件系统和挂载点
df -h                           # 查看已挂载文件系统的空间使用
du -sh ./*                      # 查看当前目录下各项占用
findmnt                         # 查看挂载关系
blkid                           # 查看文件系统 UUID，通常需要 sudo
mount | less                    # 查看当前挂载信息

ext4 仍然是成熟、广泛使用的 Linux 文件系统，并没有被淘汰。btrfs 提供写时复制、快照、校验和等功能，但其管理方式和适用场景不同，不能简单地说一定优于 ext4。选择文件系统时应考虑可靠性需求、备份方式、工具支持和团队经验

Windows 常用 NTFS。Linux 可以通过相应驱动读写 NTFS；Windows 默认不能直接访问普通 Linux ext4 分区，但 WSL 或第三方工具可能提供特定访问方式

UUID 通常用于稳定标识文件系统或分区，不等同于传统意义上的“设备号”。永久挂载通常配置在 /etc/fstab，修改前必须备份并用以下命令检查：

sudo mount -a

格式化会创建新的文件系统，并可能使原有数据无法访问。mkfs、fdisk、parted、dd 等命令可能造成不可逆的数据丢失；执行前必须用 lsblk 再次确认设备路径和备份。

十一、Linux 启动时发生了什么

典型启动流程可以简化为：

  1. 固件阶段：BIOS 或 UEFI 初始化平台硬件，并寻找可启动项；
  2. 引导阶段：GRUB、systemd-boot、U-Boot 或 rEFInd 等引导程序加载 Linux 内核，通常还会加载 initramfs；
  3. 内核阶段：内核初始化 CPU、内存、驱动和基础子系统，并解析内核命令行；
  4. 早期用户空间：initramfs 中的工具加载启动所需模块，找到并挂载真正的根文件系统；
  5. 用户空间初始化：内核启动 PID 1，主流桌面和服务器发行版通常是 systemd；
  6. 服务和登录环境：systemd 启动服务、网络和显示管理器，最终出现命令行或图形登录界面。

设备树常见于 ARM 和嵌入式平台，用来描述不能由硬件自动枚举的设备及其资源。它与 BIOS/UEFI 都涉及硬件描述和启动，但职责、数据格式和运行方式并不相同，不能简单视为同一种东西。

启动问题常用的检查方法：

journalctl -b                    # 查看本次启动日志
journalctl -b -1                 # 查看上一次启动日志
dmesg --level=err,warn           # 查看内核警告和错误，权限因系统而异
systemd-analyze blame            # 查看各服务启动耗时
systemctl --failed               # 查看失败的服务

十二、容器、虚拟机和 Python 虚拟环境

这三者都能提供隔离，但隔离的层级不同。

Python 虚拟环境

隔离 Python 包，不隔离操作系统：

python3 -m venv .venv
source .venv/bin/activate
python -m pip install <package>
deactivate

pyenv 主要用于管理多个 Python 版本；venv 用于创建轻量虚拟环境；Conda 同时管理环境、Python 版本和非 Python 依赖。三者解决的问题有重叠，但并不完全相同。

容器

Docker 和 Podman 通过内核能力隔离进程、文件系统和网络。容器共享宿主机内核，启动快、易于部署，但不等于完整虚拟机，也不是绝对的安全边界。

一个基础工作流如下：

docker pull ubuntu:24.04
docker run --rm -it ubuntu:24.04 bash
docker ps -a
docker images

应使用 Dockerfile 或 Compose 文件记录环境，不要只在运行中的容器里手工安装软件。数据需要通过卷或绑定挂载持久化。

Podman 的命令体验与 Docker 相近，并支持无守护进程和无 root 运行。Distrobox 基于 Podman 或 Docker，为桌面 Linux 提供与宿主环境集成较深的发行版容器，适合开发工具隔离，但它仍然共享宿主机内核。

虚拟机

虚拟机运行完整的客户机操作系统和内核，隔离更完整，也更适合测试不同内核、系统启动和高风险操作，但资源开销通常高于容器。

十三、深入学习路线

  1. Shell 与文本处理：管道、重定向、退出码、grep、find、sed、awk、xargs
  2. 权限与安全：用户组、ACL、sudoers、SSH 加固、防火墙、SELinux 或 AppArmor
  3. 进程与服务：信号、作业控制、cgroups、systemd unit、日志管理
  4. 网络：TCP/IP、端口、DNS、路由、NAT、抓包和代理
  5. 存储：分区、文件系统、LVM、RAID、快照和备份恢复
  6. 开发工具链：Git、编译器、Make、CMake、调试器和包构建
  7. 容器与部署：镜像分层、Compose、容器网络、卷和最小权限
  8. 内核与硬件：系统调用、内核模块、设备树、udev、字符设备和驱动模型
  9. 机器人与嵌入式：交叉编译、串口、CAN、实时性、ROS 2、DDS 和硬件接口
